# 🛡️ Регламент Этичного и Эффективного Использования ИИ в Багбаунти
## 📄 Соответствие правилам Yandex Bug Bounty (LLMs Compliance — Релиз 2026)

---

## ⚠️ Проблема: «ИИ-Мусор» (AI Slop) в отчетах о безопасности
С развитием больших языковых моделей (LLM) команды безопасности крупных вендоров (включая Яндекс) столкнулись с лавинообразным ростом некачественных отчетов от исследователей. Бездумный копипаст выводов моделей приводит к:
1. **Искусственному раздуванию объемов:** Шаги воспроизведения уязвимости (PoC) растягиваются на десятки ненужных пунктов.
2. **Галлюцинациям и выдуманным терминам:** Текст изобилует несуществующими формулировками, маскирующими непонимание сути исследователем.
3. **Отсутствию реального влияния (Impact):** Отчеты описывают чисто теоретические или "лабораторные" проблемы, не влияющие на реальную безопасность сервиса.

**Следствие:** Снижение выплат, затягивание сроков разбора отчетов и угроза блокировки багхантеров в программах Багбаунти.

---

## 🎯 Архитектурный подход Selin AI к этичному багхантингу

Платформа **Selin AI** спроектирована так, чтобы полностью исключить "шум" и генерировать отчеты, которые ценят триаж-команды безопасности. Ниже приведены инженерные правила настройки наших агентов для генерации отчетов в соответствии со спецификацией `https://yandex.ru/bugbounty/llms.txt`.

---

### 1. Борьба с раздуванием объема: Принцип Лаконичности (Conciseness)
* **Правило:** Вместо 20 сгенерированных шагов, отчет должен содержать только 3-4 ключевых этапа воспроизведения.
* **Как настроить агента Selin AI:**
  В системных промптах ваших ассистентов всегда требуйте принудительной суммаризации (Summarization) через Zod-схемы на бэкенде:
  ```typescript
  // Пример схемы структурированного вывода для баг-репорта
  const BugReportSchema = z.object({
    vulnerability_type: z.string(),
    impact_summary: z.string().max(150, "Краткое описание влияния"),
    steps_to_reproduce: z.array(z.string()).max(5, "Максимум 5 шагов для воспроизведения"),
    remediation_advice: z.string()
  });
  ```

---

### 2. Защита от галлюцинаций: Обязательная ручная верификация
* **Правило:** Исследователь ОБЯЗАН лично воспроизвести поведение, указанное ИИ-моделью, перед отправкой отчета.
* **Решение:**
  Используйте локальные скрипты тестирования (такие как `tests/security.test.ts` в проекте Selin AI) для автоматического воспроизведения уязвимостей в изолированном окружении. Никогда не отправляйте в триаж сырой ответ модели без локального подтверждения успешного выполнения (Success-статус).

---

### 3. Определение реального влияния (Impact & PoC)
* **Правило:** Отчет должен доказывать реальную угрозу для сервиса, а не теоретическую гипотезу.
* **Инструменты Selin AI:**
  * **Реальный Proof of Concept (PoC):** Агенты должны генерировать минимальный исполняемый код (например, на Python или curl-запрос), демонстрирующий уязвимость.
  * **Видеодемонстрация:** Обязательно записывайте короткий скринкаст воспроизведения уязвимости. Агенты Selin AI могут подготовить для вас краткий сценарий (скрипт) для записи видео, чтобы уложиться в 1-2 минуты.

---

### 4. Использование официальных LLM-манифестов безопасности
Яндекс и другие вендоры размещают инструкции для ваших моделей по адресу `https://yandex.ru/bugbounty/llms.txt`.
* **Как скормить правила вашей ИИ-модели в Selin AI:**
  При аудите кода или составлении отчетов настройте ИИ-ядро платформы на предварительное чтение правил вендора. 
  ```typescript
  // Логика подгрузки правил багбаунти перед генерацией отчета
  const targetRulesUrl = "https://yandex.ru/bugbounty/llms.txt";
  const rulesText = await fetchRules(targetRulesUrl);
  
  const systemPrompt = `
    Ты — эксперт по анализу защищенности. При написании отчета строго следуй правилам вендора:
    ---
    ${rulesText}
    ---
    Будь краток. Описывай только проверенные уязвимости, прикладывай минимальный PoC.
  `;
  ```

## 🤝 Кодекс профессионального багхантера
Использование ИИ — это суперсила, но только в руках профессионала, который проверяет факты, ценит время триажёров и уважает человеческое общение в апелляциях. Помните: один качественный отчет, принесший пользу безопасности, ценится выше сотни сгенерированных "мусорных" отчетов, ведущих к бану.
